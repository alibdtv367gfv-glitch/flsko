# NeuralRouter في Flsko

يستخدم Flsko طبقة توجيه آمنة لاختيار مزود الذكاء الاصطناعي المتاح تلقائيًا. لا تعتمد الطبقة على كشط صفحات الويب أو Reverse Engineering أو تجاوز حدود الخدمات؛ كل مزود يجب أن يملك واجهة عامة موثقة أو تكاملًا صريحًا قابلًا للصيانة.

## السلوك

يرتب الـRouter المزودات حسب الأولوية، يتجاوز المزود المعطل مؤقتًا، وينتقل إلى البديل عند فشل الطلب. عند نجاح المزود تُصفّر حالته، وعند الفشل يُسجل سبب مختصر ويُعطّل المزود لمدة 60 ثانية لتجنب حلقات إعادة المحاولة والضغط المتكرر. حالة المزودات الحالية في ذاكرة Worker وتظهر في `media.status`؛ لذلك قد تعود إلى الحالة الابتدائية عند نقل الطلب إلى isolate جديد.

## المزودات الحالية

| النوع | المزود | الدور |
|---|---|---|
| المحادثة | Hugging Face Router | المزود الحالي عبر واجهة OpenAI-compatible موثقة |
| الصور | مزود مفتوح مهيأ اختياريًا ثم Pollinations Flux | fallback تلقائي |
| الفيديو | Wan-AI/Wan2.1 Gradio | طابور غير متزامن، لا يُعرض كملف مكتمل قبل وصوله |
| الموسيقى | غير مهيأ | لا يُنشأ ملف وهمي ولا يُدّعى توفر مزود |

## التطوير اللاحق

يمكن نقل حالة الصحة من الذاكرة إلى D1 عند الحاجة إلى Circuit Breaker مشترك بين جميع Worker isolates. يجب إضافة مزودات جديدة فقط بعد اختبار endpoint الموثق، تسجيل حدوده، وإضافة اختبار نجاح وفشل قبل تفعيلها في الإنتاج.
