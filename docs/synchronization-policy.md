# سياسة مزامنة Flsko

هذه قاعدة تشغيلية دائمة لمشروع Flsko: لا يُعتبر أي إصلاح أو طلب مكتملًا قبل مزامنته والتحقق من الوجهات المرتبطة.

## الوجهات المؤكدة

| الوجهة | الدور | إجراء المزامنة |
|---|---|---|
| مستودع GitHub `alibdtv367gfv-glitch/flsko` | المصدر القابل للتعديل والنسخ البرمجي | تحديث الملفات، الفحوص، ثم دفع التغييرات عند توفر صلاحية المستودع |
| Manus WebDev | موقع التطبيق والمعاينة | حفظ checkpoint بعد كل تعديل واجهة أو منطق داخل التطبيق |
| Cloudflare Worker `flsko-api.flsko.workers.dev` | API والإنتاج السحابي | نشر Worker بعد أي تعديل في `cloudflare/worker.ts` أو إعداداته، ثم فحص health |
| الموقع الخاص المحمي | وجهة ثانوية للتطوير | لا تُعد متصلة إلا بعد ظهور رابط أو مشروع أو remote صريح؛ لا يجوز الادعاء بمزامنتها قبل التحقق |

## قائمة التحقق بعد كل طلب

1. تحديد الملفات والوجهات المتأثرة.
2. تشغيل TypeScript والاختبارات المناسبة.
3. حفظ checkpoint في Manus إذا تغير مشروع التطبيق.
4. نشر Worker وفحص `/api/health` إذا تغير backend أو Cloudflare.
5. فحص Git status وremote ونسخة الوجهة.
6. فحص الموقع الخاص المحمي إذا كان مربوطًا؛ وإذا لم يكن مربوطًا، التصريح بذلك بدل اعتبار المزامنة مكتملة.
7. ذكر نتيجة المزامنة بوضوح في الرد التالي.

## قاعدة الأمان

لا تُنسخ الأسرار أو Client Secret أو الرموز إلى GitHub أو ملفات عامة. المزامنة تعني الكود والإعدادات غير السرية فقط، بينما تبقى الأسرار في Secret Manager أو Cloudflare Secrets.
